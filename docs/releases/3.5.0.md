# VICE 3.5: deeper application discovery and stronger evidence

VICE 3.5 follows the application it observes. Routes, forms, parameters, API responses and read-only GraphQL requests can guide subsequent security checks, including paths outside conventional API directories.

Browser XSS findings now require a unique execution marker in Chromium. Injection checks compare responses with controls, and login checks follow the observed form handler using a bounded set of synthetic submissions. Supabase publishable keys are recognized as public configuration rather than secrets. Storage findings inspect accessible content before reporting exposure.

Scoring better reflects confirmed impact and incomplete coverage. Related findings with an explicit shared cause are counted together. Existing reports retain their original scores; new reports identify the scoring version used.

In a targeted local benchmark of 13 synthetic scenarios, VICE 3.5 detected 11 of 11 expected defects, compared with 2 of 11 for 3.4.1. Three targeted false positives fell to zero. Median time for the complete corpus decreased by 36.2% across three repetitions. These are results for this corpus, not an estimate of detection or speed across production sites.

The `runScan` entry point and full, light and custom profiles remain available. Node.js 22.12 or later is required. Browser checks require Chromium.

```sh
npm install -g vice-security@3.5.0
```
