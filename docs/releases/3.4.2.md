# VICE 3.4.2 release preparation

Status: local candidate, not pushed, tagged or published.

## GitHub release draft

### More application context, stronger evidence

VICE 3.4.2 uses the routes, forms, parameters and API calls observed during the
crawl to guide its checks. Nested application pages and JSON endpoints outside
conventional API paths can now feed subsequent modules.

XSS confirmation requires a unique marker to execute in Chromium. Input probes
compare responses against controls. Login auditing follows the actual form
handler and limits itself to three synthetic submissions on the audited origin.

Supabase publishable keys are recognized without being sent as bearer JWTs.
Public configuration keys are informational; storage findings inspect actual
object content. CSP, DMARC, TLS uncertainty, WordPress REST routes, realtime
subscriptions and AI endpoint discovery receive targeted improvements.

### Scoring changes

The engine retains its severity penalties and applies impact ceilings:

- Confirmed critical finding: maximum 39.
- Confirmed high finding: maximum 69.
- Partial coverage: maximum 89; incomplete coverage: maximum 49.
- Explicitly shared causes receive one penalty at their strongest severity.

These are scoring policy thresholds, not probabilities of compromise. Historical
scores are unchanged. Compare reports using scoring version `2026.09.23.1`.
A complete scan containing only minor hardening findings can still score highly.

### Compatibility and limits

Node 22.12 or later remains required. The `runScan` entry point and full, light
and custom profiles are preserved. Browser-dependent checks need Chromium.
Generic engine changes are shared with Platform; private session and egress
adapters remain in the Platform repository.

Programmatic object-authorization comparison accepts two caller-supplied
`authorizationProfiles`, each with a distinct `userId` and credential `headers`.
It compares observed same-origin JSON reads and reports potential unauthorized
sharing without exporting returned values. The SaaS does not provision a second
identity automatically. Stored-XSS persistence, arbitrary JSON mutations and
exhaustive storage traversal are not part of this release.

Validation uses local synthetic fixtures and the existing regression suites.
A targeted local corpus contains 13 scenarios with 11 known defects, protected
variants and three false-positive traps. Three Platform repetitions detect 11/11
instead of 2/11, remove the three targeted false positives, and reduce median
complete-corpus time from 132.831 s to 84.718 s (36.2%). A separate OSS pass
reproduces the detection results. These are local corpus results, not production
recall estimates. See `benchmark/results-3.4.2.json` and the reproducible harness.
Production precision and latency improvements still require measurement.

Local validation on 2026-09-23: OSS 345/345, Platform engine 389/389,
worker 65/65. The packed npm artifact installs independently with scripts and
optional browser installation disabled. Its `runScan` call detects an exposed
credential field on a local Supabase fixture, returns score 39 and no errors.
Browser execution is covered separately by the repository test suites.

Reviewed artifact: `vice-security-3.4.2.tgz`, 93 entries,
SHA-1 `3defce4db98756ac2080e322aabff0efdb9f836b`.
Private Platform adapters are excluded.

## Publication sequence, after explicit authorization

1. Review the local commits and validation evidence in both repositories.
2. Obtain explicit push authorization before sending the OSS branch or tag.
3. Publish the reviewed npm artifact and verify its version and integrity.
4. Publish the GitHub release for that exact tag and artifact.
5. Publish approved LinkedIn and Discord text.
6. Deploy Platform's candidate only on explicit production deployment request.

## LinkedIn draft, to use after publication

VICE 3.4.2 est disponible.

Cette version améliore la façon dont le moteur comprend l'application auditée :
